# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

This repo serves two coexisting goals:

1. **AI workshop teaching material** — `.agents/skills/` holds shared Agent Skills (`SKILL.md` prompt scripts) used as exercises across AI tools. The directories `.claude/skills`, `.cursor/skills`, `.codex/...`, `.gemini/...`, `.github/skills`, `.opencode/...`, `.factory/...` are **symlinks into `.agents/`** so the same Skill set surfaces in every assistant. Edit Skills only in `.agents/skills/`.
2. **Vehicle management MVP** — `src/` is a real Vite + React + TS + MSW SPA used as the substrate for the workshop exercises (vehicles CRUD, employees CRUD, dashboard, modification history). It was built via the OpenSpec workflow.

## Commands

```bash
npm install
npm run dev          # Vite dev server on http://localhost:5173 (MSW auto-enabled via .env.development)
npm run build        # tsc -b && vite build  → dist/
npm run preview      # serve built bundle locally
npm run lint         # ESLint over the whole repo
npm run lint:fix
npm test             # Jest (run via node --experimental-vm-modules)
npm run test:watch
```

Run a single Jest test file: `npm test -- src/skills/__tests__/echo.test.js`
Run by name: `npm test -- -t "returns the same string"`

A Husky `pre-commit` hook runs `npm run lint` and `npm test` **in parallel** and prints both outputs in labeled sections — fix both before retrying a commit.

## Two distinct lint/test targets

ESLint config (`eslint.config.js`) deliberately splits two universes — when adding files, place them on the correct side:

- **Workshop skills** — `src/skills/**/*.js`, plain Node ESM + Jest. Stricter rules: `no-var`, `prefer-const`, `eqeqeq`, `no-unused-vars: error`, `no-console: warn`. Tests use Jest globals (declared as readonly in config).
- **Frontend SPA** — `src/**/*.{ts,tsx}`, typescript-eslint recommended + `react-hooks` + `react-refresh/only-export-components`. Unused vars/args are allowed when prefixed with `_`.
- **shadcn-generated** — `src/components/ui/**` has `react-refresh/only-export-components` disabled because shadcn's generated components co-export hooks/constants. Don't hand-edit these files — wrap them if you need customization.

## Frontend architecture (vehicle-mgmt-mvp)

Stack: Vite 5 + React 18 + TypeScript, TailwindCSS v3 + shadcn/ui (New York / Slate, see `components.json`), React Router v6, React Hook Form + Zod, Recharts, MSW v2. No react-query, no Redux. Path alias `@` → `src/` (configured in both `vite.config.ts` and `tsconfig`).

### Auth + routing flow
- `AuthContext` (`src/lib/auth-context.tsx`) is the only state container; session is `{ token, user }` persisted in `localStorage` under `vmgmt.session`.
- `src/router.tsx` wraps the layout in `<ProtectedRoute>`; `/employees` is additionally wrapped in `<AdminRoute>`.
- `src/lib/api.ts` is the **only** fetch wrapper — it auto-attaches `Authorization: Bearer <token>` and converts non-OK responses into `ApiException` (carrying `status`, `message`, optional `field`). All page-level code should go through `api.get/post/put/del`.

### MSW mock backend
- Worker is started conditionally in `src/main.tsx` based on `import.meta.env.VITE_USE_MSW === "true"` (set in `.env.development`). Bypassing MSW (real backend) just requires flipping that env var.
- Service worker file is `public/mockServiceWorker.js` — generated by `npx msw init`, do not hand-edit.
- **Data is in-memory.** `src/mocks/db.ts` (vehicles, employees, users) and `src/mocks/audit-log.ts` reset on every page reload. Do not write tests or features that assume persistence across reloads.
- Token format: `mock-token-<userId>-<role>`. Decoded in `src/mocks/lib/auth.ts` by **matching role suffix from the end** (so `userId` may legally contain `-`). Preserve that behavior if extending.
- Handlers under `src/mocks/handlers/` share `requireAuth(request, requiredRole?)` and `errorResponse(status, message, field?)` from `src/mocks/lib/`. Error envelope is always `{ message, field? }` — keep new handlers consistent.
- Validation reuses front-end Zod schemas from `src/lib/schemas.ts` (`safeParse` → 400 with `issue.message` and `issue.path[0]` as `field`). **Do not duplicate schemas in handlers.**

### Modification history (audit log)
- `recordEvent()` in `src/mocks/audit-log.ts` is called **only on successful mutations** inside vehicle / employee handlers. Failures (validation, 401, 403, 404, 409) MUST NOT write events. An `update` whose `diff()` is empty MUST NOT write an event.
- `diff(prev, next)` only inspects keys present in `next` (so internal fields like `id` / `createdAt` won't leak as changes). It uses shallow equality — sufficient for the current flat schemas; extend it if you introduce nested fields.
- Role-based filtering for `/api/history` happens **server-side** in `src/mocks/handlers/history.ts`. Front end MUST NOT filter — `user` role sees all vehicle events plus only employee events where `resourceId === currentUser.employeeId` (the latter is server-only, never returned in `/api/auth/me` or token).

## OpenSpec workflow

Specs live in `openspec/specs/<capability>/spec.md` (six capabilities: `auth`, `dashboard`, `vehicle-management`, `employee-management`, `mock-api`, `modification-history`). Historical proposals are archived under `openspec/changes/archive/<date>-<slug>/`.

When the user wants new features or contract changes, prefer running through an OpenSpec change (`openspec-new-change` / `openspec-propose` / `opsx:*` skills) — **don't edit `openspec/specs/` directly**, propose a change and let the flow update specs on archive/sync.

## Switching to a real backend

If asked to wire to a real API: (1) set `VITE_USE_MSW=false` (or remove `enableMocking()`), (2) change base URL handling in `src/lib/api.ts`, (3) replace the mock token round-trip in `auth-context.tsx` with real JWT, (4) reconcile `src/lib/schemas.ts` with the real contract.
